# mdview 使用说明与故障排查

> 本文档可使用 mdview 打开：`Ctrl+E` 查看源码，`Ctrl+T` 查看大纲。
> 项目主页：[README.md](../README.md)
>
> 下文中的 `D:\mdview` 指仓库所在路径，请替换为实际位置。

---

## 一、项目定位

一个**仅用于本机**的 Markdown 阅读器。双击 `.md` 文件即用系统默认浏览器打开，支持排版、代码高亮、目录树与图片。

与常见 Markdown 编辑器的区别在于：**只做阅读，不做编辑**，并将运行时依赖控制为零。

| 特性 | 说明 |
|---|---|
| 零依赖 | 只用 Node.js 内置模块，不用 `npm install`，不请求外部服务、不引 CDN |
| 纯本机 | 服务只监听 `127.0.0.1`，不对外开放 |
| 零常驻 | 所有文档共用同一个后台服务；关掉浏览器标签页约 45 秒后自动退出，兜底空闲 15 分钟退出 |
| 可回滚 | 只改 `HKCU`（当前用户），不需要管理员，卸载脚本按备份还原 `ProgId` 与「打开方式」 |
| 单文件 | 全部逻辑在 `server.mjs` 一个文件里，方便审计 |

## 二、装了什么、装在哪

运行安装脚本后产生的全部变更如下：

| 位置 | 内容 | 备注 |
|---|---|---|
| `%LOCALAPPDATA%\mdview\` | 程序文件（装完后约 200 KB 文本） | 用户目录，不是系统目录 |
| `HKCU\Software\Classes\mdview.md` | 注册 ProgID | 当前用户注册表 |
| `HKCU\...\FileExts\.md\OpenWithProgids` | 「打开方式」条目 | 同上，共 5 个扩展名 |
| `HKCU\...\FileExts\.md` 的 `ProgId` | 默认处理程序 | 仅在该扩展名原本没有默认程序时写入 |
| 用户 `Path`（可选） | 安装目录 | 只有加 `-AddPath` 时才写 |

**不会发生的事**：不写 `HKLM`、不需要管理员、不装服务或驱动、不设开机启动、不改防火墙、不主动请求外部服务。

**原始状态备份**在**安装目录**下的 `assoc-backup.json`（默认 `%LOCALAPPDATA%\mdview`；用 `-InstallDir` 换过位置时备份跟着走，卸载要传同一个 `-InstallDir`）。卸载会照着还原 `ProgId` 与「打开方式」条目；`UserChoice` 由 Windows 哈希保护，脚本改不了，只有你自己在系统界面里改。

### 后台进程数量

无论打开多少文档，后台始终只有一个进程。实测数据：

| 操作 | 后台进程数 |
|---|---|
| 打开 `D:\notes\project-a` 里 3 个文档 | 1 |
| 再打开 `D:\notes\project-b` 里 2 个文档 | 1 |
| 打开第 100 个文档 | 1 |

原理：服务进程不按文件数量创建，一个进程服务全部文档；打开新文档时仅向白名单追加记录，不创建新进程。可通过以下命令验证：

```text
Invoke-RestMethod "http://127.0.0.1:7717/health" | Select-Object pid, roots, liveTabs
```

`roots` 为已服务过的目录清单，`pid` 保持不变。

### 自动退出机制

两套机制，先满足者生效：

| 触发条件 | 时间 | 说明 |
|---|---|---|
| **关闭浏览器标签页** | 约 45 秒后 | 主要机制。标签页持续上报存活状态，关闭最后一个后服务自行退出 |
| 完全没有任何活动 | 15 分钟后 | 兜底机制。适用于标签页崩溃、进程被强制结束等异常情况 |

多标签页时，只有关闭最后一个标签页才会退出；关闭中间标签页不影响。

如需调整时间，可设置环境变量（`0` 表示永不自动退出）：

```text
$env:MDVIEW_IDLE_MINUTES = 5
```

### 全部环境变量

| 变量 | 作用 |
|---|---|
| `MDVIEW_IDLE_MINUTES` | 空闲退出分钟数，`0` 表示永不（默认 15） |
| `MDVIEW_HOME` | 指定数据目录（`server.json` / `recent.json` / 日志）。测试时用于隔离，不影响正在运行的服务 |
| `MDVIEW_DEBUG` | 打印更多调试信息 |
| `MDVIEW_NO_OPEN` | 仅用于测试：设为 `1` 时 `openExternal()` 直接返回成功，不启动系统程序（`npm test` 用它避免弹窗） |

立即停止服务：

```text
mdview stop
```

**不会执行的行为**：开机自启、常驻托盘、注册为 Windows 服务、加入计划任务。未双击 `.md` 时不存在对应进程。

## 三、日常使用

### 两种模式

| 模式 | 界面 | 适用场景 |
|---|---|---|
| **专注模式**（默认） | 不显示左侧目录，仅展示当前文档 | 阅读单篇文档 |
| **浏览模式** | 左侧显示目录树与「最近打开」列表 | 在多篇文档之间切换 |

按 `Ctrl+B` 或点击标题栏的 **☰** 切换；选择会被记住，下次打开沿用上次的模式。

### 打开文档

```text
mdview "D:\notes\某文档.md"          # 装了 -AddPath 之后（新开终端生效）
node server.mjs "D:\notes\某文档.md" # 没加 PATH 时用这个
& "$env:LOCALAPPDATA\mdview\mdview-launch.cmd" "D:\notes\某文档.md"   # 或直接用启动脚本
```

最简单的方式是**双击任意 `.md` 文件**。

### 切换文档不会丢上下文

标题栏有个 **「打开 ▾」** 按钮（快捷键 `Ctrl+O`），点开就是：

- **最近打开**：按时间倒序列出已读过的文件与目录，点击即可跳转。
- 打开文件… / 打开文件夹…

浏览模式下，左侧第一栏也是「最近打开」，第二栏才是当前目录的树。

「最近打开」记录保存在 `%LOCALAPPDATA%\mdview\recent.json`，最多 30 条；文件被删除后对应条目会自动移除，同一路径只保留一条。

### 浏览一个目录

```text
mdview "D:\notes"
```

左侧目录树会列出该目录（含子目录，最多 6 层）下所有 Markdown，点文件名即可切换。

### 界面快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl+E` | 源码 / 预览切换 |
| `Ctrl+B` | 专注模式 / 浏览模式切换（侧栏） |
| `Ctrl+T` | 大纲（跟随滚动高亮当前章节） |
| `Ctrl+D` | 深色 / 浅色切换（默认跟随系统） |
| `Ctrl+F` | 聚焦侧栏筛选框（按文件名过滤） |
| `Ctrl+O` | 打开「最近打开 / 打开文件」下拉 |
| `Ctrl+P` | 打印 / 导出 PDF |
| `F5` / `Ctrl+R` | 重新加载当前文档 |

其它：

- 代码块**鼠标悬停**右上角出现「复制」按钮。
- 文档里的**相对链接**可以直接点，会在同一窗口打开目标 `.md`。
- 指向本地文件的链接会带一个 📎，点击交给系统默认程序打开。出于安全，只有图片、音视频、PDF、压缩包和文本会打开，`.exe`/`.lnk`/`.bat` 等类型会被拒绝。
- 文档里的**原始 HTML 按字面显示**，不会当标记渲染；`javascript:` 链接被丢弃。
- 可以直接把文件**拖进浏览器窗口**打开（浏览器拿得到真实路径时）。

### 命令行参考

```
mdview <文件.md>       打开文档（必要时自动起后台服务）
mdview <文件夹>        浏览该文件夹下所有 Markdown
mdview serve           前台运行服务（调试用，Ctrl+C 停止）
mdview status          查看是否在运行、端口、PID
mdview stop            停止后台服务
mdview --help          帮助
mdview --version       版本
```

`mdview open` 额外支持 `--no-open`（只起服务不弹浏览器）和 `--port N`（指定端口）。

## 四、升级 / 卸载

### 升级

将新版本的 `server.mjs` 覆盖后重新运行安装脚本即可（安装是幂等的，可重复执行）：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\mdview\windows\install.ps1"
```

### 卸载

```text
# 1) 撤销注册表与 PATH（按备份还原 ProgId 与「打开方式」；UserChoice 需手动改）
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\mdview\windows\install.ps1" -Remove

# 2) 删文件
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\mdview"
```

也可以直接使用项目目录中的脚本（内容相同）：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\mdview\windows\install.ps1" -Remove
```

### E1 双击 `.md` 没用 mdview 打开

**原因**：Windows 11 的默认程序由 `UserChoice`（带哈希签名）决定，脚本无法修改，需要在系统界面中确认一次。

**处理**：

1. 右键任意 `.md` → **打开方式** → **选择其他应用** → 选 **mdview** → 勾选 **始终使用**；
2. 或者重新运行安装脚本并加 `-Default`，由脚本弹出该对话框：
   ```text
   powershell -NoProfile -ExecutionPolicy Bypass -File "D:\mdview\windows\install.ps1" -Default
   ```

**确认当前状态**：执行以下命令，查看 `.md` 当前指向的程序：

```text
(Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.md\UserChoice" -EA SilentlyContinue).ProgId
```

- 输出 `mdview.md` → 已经是 mdview；
- 输出别的（如 `Applications\notepad.exe`）→ 被别的程序占着，按上面第 1 步改；
- 什么都不输出 → 没有 `UserChoice`，此时起作用的是 `HKCU\Software\Classes\.md` 的默认值。

### E2 双击时黑色窗口闪一下

**原因**：关联的启动命令走了 `.cmd`（会先创建一个控制台窗口），而不是无窗口的 `.vbs`。

**确认**：

```text
(Get-ItemProperty "HKCU:\Software\Classes\mdview.md\shell\open\command").'(default)'
```

正确输出应该以 `wscript.exe //nologo` 开头并指向 `mdview-silent.vbs`，形如：

```
wscript.exe //nologo "C:\Users\<你>\AppData\Local\mdview\mdview-silent.vbs" "C:\Program Files\nodejs\node.exe" "C:\Users\<你>\AppData\Local\mdview\server.mjs" "%1"
```

**处理**：如果指向的是 `.cmd`，重跑一次安装脚本即可修正（它总是写 `.vbs` 那条命令）。

---

### E3 服务起来了但浏览器没弹出

**原因**：`node` 通过 `rundll32.exe url.dll,FileProtocolHandler` 调系统默认浏览器，若被安全软件拦截就会静默失败（服务照常运行，只是没开窗口）。

**处理**：直接手动访问。先拿端口：

```text
Get-Content "$env:LOCALAPPDATA\mdview\server.json" -Raw
```

然后用返回的端口拼接地址：`http://127.0.0.1:<端口>/view?f=<文件的 base64url 编码>`。另一种方式是重新在终端中运行一次：

```text
node "$env:LOCALAPPDATA\mdview\server.mjs" "D:\notes\某文档.md"
```

它会打印出最终 URL（可用 `--no-open` 只打印不开）。

### E4 「服务启动超时（端口 7717）」

**含义**：启动器起了子进程，但 8 秒内没等到可用的服务。

**按顺序查**：

1. **查看子进程日志**（多数情况下原因记录在此）：
   ```text
   Get-Content "$env:LOCALAPPDATA\mdview\server.log" -Tail 20
   ```
2. **看端口有没有被别的程序占着**：
   ```text
   netstat -ano | Select-String ':7717'
   ```
   如果被占，mdview 会自动往 7718、7719… 顺延，正常情况不影响使用。
3. **确认 Node 版本 ≥ 20**：
   ```text
   node --version
   ```
4. **以前台方式运行一次**，错误信息会直接输出到终端：
   ```text
   node "$env:LOCALAPPDATA\mdview\server.mjs" serve --port 7799
   ```
5. 仍不行就删掉状态文件重来：
   ```text
   Remove-Item "$env:LOCALAPPDATA\mdview\server.json" -Force -EA SilentlyContinue
   ```

### E5 后台进程累积与 `status` 状态不符

正常使用时后台**始终只有 1 个**进程，与打开的文档数量无关（详见第二节「后台进程数量」）。

**关于 `status` 显示「未运行」**：状态文件 `server.json` 只能记录一个服务；若曾手动关闭、或同时存在新旧两个服务，`status` 可能读不到当前实例。这**不代表异常，也不影响使用**；按端口探测更可靠：

```text
foreach ($p in 7717,7718,7719,7720) {
  try { Invoke-RestMethod "http://127.0.0.1:$p/health" | Select-Object @{n='port';e={$p}}, pid, roots } catch {}
}
```

如果确实存在多个 mdview 进程，那是**旧版本的缺陷**（已修复）：旧版 `readState()` 会额外要求状态文件里有一个从不写入的 `token` 字段，导致读状态永远失败 → 每打开一次文档就新起一个服务，旧的变成僵尸。

**处理**：用最新版覆盖并重装（覆盖 `server.mjs` 后重新运行 `install.ps1`），清理残留进程。注意**只关闭 mdview 自身的进程**，避免影响其它 Node 程序：

```text
foreach ($p in 7717,7718,7719,7720) {
  try { Invoke-RestMethod "http://127.0.0.1:$p/api/shutdown" -Method Post -Headers @{'X-Mdview'='1'} -TimeoutSec 2 | Out-Null } catch {}
}
Remove-Item "$env:LOCALAPPDATA\mdview\server.json" -Force -EA SilentlyContinue
```

新版另有兜底机制：**关闭最后一个浏览器标签页约 45 秒后服务自动退出**。

### E6 图片显示「图片找不到」

**原因**：出于安全，服务只允许读取**你打开过的文件/目录**范围。文档里引用了范围之外的图片（比如 `../../assets/a.png` 跳出了当前目录）时读不到。

**处理**：用 mdview 打开图片所在的那个目录（`mdview "D:\assets"`），让该目录进入白名单，再回来看文档；或者把文档和它引用的资源放在同一个根目录下。

**另一个常见原因是路径本身写错了**：大小写不符、中文文件名编码不一致、`\` 与 `/` 混用。把鼠标移到图片上，右键「复制图片地址」看服务端实际请求的路径。

---

### E7 点链接提示 403「该路径不在允许范围内」

原因与 E6 相同，属于预期行为：未经打开的路径一律拒绝，避免文档中的本地链接扩大白名单范围。
（`file:///C:/...` 这类写法在解析阶段即被丢弃，不生成链接；浏览器同样禁止从 http 页面跳转到该协议。）

处理方式同上：先用 mdview 打开目标所在目录。

---

### E8 文档过大打不开

单个文本文件上限 **8 MB**，超过会返回「文件过大」。

**处理**：拆分文档，或者临时用编辑器打开。附件（图片/PDF/视频）单独走 `/asset`，上限 64 MB，不受此限制。

---

### E9 中文乱码

**原因**：文件不是 UTF-8 编码（老文件常是 GBK/GB2312）。

mdview 检测到 UTF-8 解码失败时会**自动改用 GBK 再解一次**，文件信息栏会标注 `· gbk`。如果仍然乱码，说明是其它编码（如 Big5、Shift-JIS）。

**处理**：把文件转成 UTF-8 保存。VS Code 里点右下角编码 → `通过编码重新打开` → 选对编码 → 再 `通过编码保存` → `UTF-8`。

---

### E10 安装脚本报 SyntaxError 或一堆乱码解析错误

**原因**：`install.ps1` 里有中文，而 Windows PowerShell 5.1 **不会自己识别 UTF-8**，必须靠文件开头的 UTF-8 BOM 来判断。如果 BOM 丢了（用某些编辑器/工具改过就会丢），5.1 会按 GBK 解析，于是报出类似这样的错：

```
+ | 妫€鏌ラ」 | 缁撴灉 |
An empty pipe element is not allowed.
```

**处理**：给文件补回 BOM（下面这段会自动判断并补齐）：

```text
$p = "D:\mdview\windows\install.ps1"
$b = [System.IO.File]::ReadAllBytes($p)
if (-not ($b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)) {
  [System.IO.File]::WriteAllText($p, [System.Text.Encoding]::UTF8.GetString($b), (New-Object System.Text.UTF8Encoding($true)))
  "BOM 已补回"
} else { "BOM 正常" }
```

**根治办法**：用 PowerShell 7（`pwsh`）跑安装脚本，它默认按 UTF-8 读取，不依赖 BOM。

---

### E11 安装脚本报 `The term '/*' is not recognized`

**原因**：脚本里混入了 C 风格注释 `/* ... */`，PowerShell 不认（当前版本已全部改成 `<# ... #>` 或 `#`）。

**处理**：确认你用的是仓库最新版的 `install.ps1`，搜索一下有没有残留：

```text
Select-String -Path "D:\mdview\windows\install.ps1" -Pattern '/\*|\*/'
```

无输出就是干净的。

---

### E12 安装目录里有 `verify.txt` / `server.json` / `server.log` 残留

**来源**：安装脚本的自检步骤会生成这些文件（旧版本还会留下 `verify.txt.err`）。

**处理**：可直接删除，不影响功能：

```text
Remove-Item -Force -EA SilentlyContinue "$env:LOCALAPPDATA\mdview\verify.txt","$env:LOCALAPPDATA\mdview\verify.txt.err","$env:LOCALAPPDATA\mdview\server.json","$env:LOCALAPPDATA\mdview\server.log"
```

**注意**：`server.json` 只在没有服务运行时才能删掉（有服务在跑时删了也没事，`status` 会显示未运行而已）。

### E13 想看日志

| 日志 | 位置 | 内容 |

### E14 卸载后 `.md` 又变回 mdview 了

**原因**：旧版卸载脚本存在缺陷（已修复）：脚本将 `exit` 写成了 `return`，卸载流程结束后继续执行，重新写入了关联。

**处理**：确认你用的是修好的版本：

```text
Select-String -Path "$env:LOCALAPPDATA\mdview\windows\install.ps1" -Pattern 'if \(Invoke-Remove\) \{ exit 0 \}'
```

有输出 = 修好的版本（在项目目录那份里，约在第 166 行）。然后再 `-Remove` 一次即可。

### E15 我指定了 `--port 7799`，但实际端口不是 7799

**原因**：指定端口被占用时，服务会从该端口开始往上顺延（7799 → 7800 → …），最终端口记录在状态文件里。

**处理**：以状态文件为准：

```text
Get-Content "$env:LOCALAPPDATA\mdview\server.json" -Raw | ConvertFrom-Json | Select-Object port,pid
```

### E16 文档打开是空白的，什么也不显示

**这是 1.0.0 中的缺陷，已在最新版本修复。** 现象：双击某个 `.md` 后浏览器打开，但正文区空白，且不显示错误。

**原因**：文件开头带 **BOM**（字节 `EF BB BF`，即 U+FEFF 零宽字符）。记事本、WPS 以「UTF-8」另存时通常会添加 BOM，其它工具导出的文件一般不带。能否正常显示**与内容来源无关，只取决于保存方式**。

JavaScript 的正则把 U+FEFF 当空白字符，导致解析器里两条判定互相矛盾，**主循环索引永不前进 → 渲染器空转 → 页面白屏**。

**判断某个文件是不是带 BOM**：

```text
$p = "D:\notes\某文档.md"
$b = [System.IO.File]::ReadAllBytes($p)
if ($b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF) { "带 BOM（会触发旧版本的白屏）" } else { "不带 BOM" }
```

**处理**：更新到最新版即可（解析入口会统一清除 U+FEFF / U+200B–200F / U+2060 / U+180E / NUL），并增加了兜底处理：**任何未推进索引的分支都会把剩余内容按纯文本输出，不会再次进入死循环**。

```text
# 更新到修复版
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\mdview\windows\install.ps1"
```

**清除 BOM**（可选，或暂不更新时使用）：

```text
$p = "D:\notes\某文档.md"
$t = [System.IO.File]::ReadAllText($p)
[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))  # $false = 不加 BOM
```

**回归测试**：`node tools/bom-repro.mjs` 覆盖 10 种隐形字符组合，全部应在 0–1ms 内完成。

## 八、已知边界

- 需要 Node.js **20+**。
- 单个文本文件上限 8 MB，附件 64 MB。
- 目录树最多递归 6 层；单次最多 6000 个条目 / 20000 个目录项 / 8 秒，任一条件到达上限即截断，
  侧栏提示「目录太大，只列出了前一部分」。
- 代码高亮的函数名识别上限 120 个字符（防止超长字母串拖慢页面）；超过的只把尾部着色。
- 非 UTF-8 会尝试按 GBK 解码；如果 GBK 解出来的替换字符反而更多，就保留 UTF-8 原文。
- **未实现**：Mermaid 图、LaTeX 公式、内嵌 iframe、跨文件搜索界面（服务端已提供 `/api/search`，界面尚未接入）。以上均为保持零依赖的取舍。
- 目录树里的 `node_modules`、`.git`、`dist`、`__pycache__` 等会被跳过。
